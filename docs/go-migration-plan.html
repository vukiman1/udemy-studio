1. Tóm tắt

Tool hiện tại là một CLI Python (~2.800 dòng core, file chính Udemy.py 2.084 dòng) tải khoá học Udemy về máy: video, phụ đề, tài liệu đính kèm, bài viết, quiz. Nó không tự tải media: phần nặng được giao cho 3 tool ngoài là yt-dlp, aria2c và ffmpeg. Phần Python làm 4 việc: đăng nhập và vượt Cloudflare, gọi API Udemy để lấy curriculum, phân loại từng lecture và chọn nguồn, rồi điều phối tool ngoài và đặt tên file.

Hiện trạng dữ liệu của bạn

  • Khoá Fundamentals of Backend Communications and Protocols: 59 video (16 GB), 8 HEVC + 51 H.264.
  • 58 cặp phụ đề _en.srt / _vi.srt đã kiểm chứng index, timing và drift.
  • 1 lecture DRM không tải được (ngoài phạm vi).

Hướng đi đã chốt

  • Backend Go (thư viện chuẩn là chính), frontend React + TypeScript strict, đóng gói 1 binary.
  • Giữ yt-dlp / aria2c / ffmpeg làm tool ngoài, không viết lại.
  • Migrate kiểu strangler: Python vẫn là chuẩn đối chiếu cho tới khi Go chứng minh cho ra kết quả giống hệt.

4. Thuật toán và ý tưởng chi tiết

4.1 Vượt Cloudflare và giả lập client

  • TLS fingerprint: Cloudflare nhận diện client qua cách bắt tay TLS (JA3/JA4) và HTTP/2 settings. Thư viện HTTP thông thường của Python hay Go có fingerprint rất dễ nhận ra. curl_cffi dùng bản curl được vá để bắt tay giống hệt Chrome 120. Session còn bỏ User-Agent của app để header khớp với fingerprint trình duyệt.
  • Request "visit": trước khi gọi API, tool gọi /api-2.0/visits/current/ để nhận cookie Cloudflare. Nếu nội dung trả về chứa challenge-platform hoặc <title>Just a moment..., tức là fingerprint bị lộ, và tool dừng lại.
  • Header app Android: các request mang client id/secret và version name của app Android Udemy (khai báo trong constants.py). Header authorization: Basic … của app bị gỡ sau khi đăng nhập, để bearer token hoặc cookie quyết định danh tính.
  • Retry: Session._get thử lại tối đa 10 lần khi gặp 502/503, nghỉ cố định 0,8 giây giữa các lần; timeout 120 giây cho phản hồi chậm.

4.2 Đăng nhập: bearer token hoặc cookie

  • Hai cách loại trừ nhau (argparse mutually exclusive group): --bearer, hoặc --browser <tên> / --browser file.
  • Bearer: gắn vào Authorization và X-Udemy-Authorization.
  • Cookie file: đọc Netscape format bằng ignore_discard=True, ignore_expires=True. Lý do: các extension export cookie phiên với expiry = 0, Python coi là đã hết hạn và bỏ đi. Tool nạp tất cả rồi chỉ xoá cookie có expiry thật sự đã qua.
  • Cookie trình duyệt: browser_cookie3.<browser>(domain_name="udemy.com"). Hạn chế: chỉ đọc profile mặc định (không truyền cookie_file).

Thuật toán đọc cookie Chrome trên macOS (sẽ viết trong Go)

  1. Tìm profile: đọc ~/Library/Application Support/Google/Chrome/Local State → profile.info_cache cho ra cặp (thư mục, tên hiển thị), ví dụ Profile 2 → "Claude browser 2".
  2. Copy <profile>/Cookies (kèm -wal, -shm nếu có) sang thư mục tạm, vì Chrome đang chạy sẽ khoá file.
  3. Đọc meta.version và các dòng cookies có host_key kết thúc bằng udemy.com.
  4. Lấy mật khẩu Keychain: security find-generic-password -w -s "Chrome Safe Storage". Lần đầu macOS hỏi quyền, người dùng chọn Always Allow.
  5. Dẫn xuất khoá: PBKDF2-HMAC-SHA1, salt saltysalt, 1003 vòng, 16 byte.
  6. Giải mã encrypted_value: bỏ tiền tố 3 byte v10, AES-128-CBC với IV là 16 dấu cách (0x20), gỡ padding PKCS7.
  7. Nếu meta.version ≥ 24: bỏ 32 byte đầu của plaintext (SHA-256 của host_key mà Chrome chèn vào trước giá trị).
  8. Kiểm tra có cookie access_token; nếu không có thì báo "hãy đăng nhập Udemy trên profile X".

Bước 5–7 lấy từ mã nguồn của nhiều thư viện độc lập (rookie, HTTP::Cookies::Chrome, nab) và khớp nhau; Phase 0 sẽ xác nhận trên Chrome 158 của bạn bằng cách so sánh hash giá trị với cookies.txt, không in giá trị ra.

4.3 Tìm course id: chuỗi fallback 6 bước

Từ URL, regex //(?P<portal_name>.+?).udemy.com/(course/)?(?P<name_or_id>…) tách ra portal (ví dụ nelisoftwares cho Udemy Business, www cho bản thường) và slug. Sau đó tìm khoá theo thứ tự, dừng ở bước đầu tiên khớp published_title hoặc id:

  1. Tìm trong khoá đã đăng ký (subscribed-courses?search=…).
  2. Toàn bộ khoá của tôi (page_size 10000).
  3. Khoá thuộc gói subscription (Personal Plan).
  4. Khoá trong các collection.
  5. Khoá đã archive.
  6. Fallback cuối, hoặc khi có cờ -sc: tải HTML trang học, tìm div.ud-component--course-taking--app, đọc JSON trong data-module-args để lấy courseId, rồi gọi API course.

4.4 Lấy curriculum và phân trang

_get_all_pages gọi trang đầu, rồi đi theo trường next cho tới hết, gộp results. Số trang ước tính = ⌈count / số phần tử trang đầu⌉, chỉ dùng để in tiến độ. Curriculum được xin kèm danh sách field rất cụ thể (CURRICULUM_ITEMS_PARAMS), page_size 200, để một lần gọi trả về đủ asset, caption, stream URL.

4.5 Dựng cây chapter/lecture từ danh sách phẳng

API trả về một danh sách phẳng, mỗi phần tử có _class là chapter, lecture, quiz, practice hoặc role-play. Thuật toán duyệt một lượt:

  • Gặp chapter: tạo chapter mới với tên "{object_index:02d} - {sanitize(title)}", reset bộ đếm lecture về 0 (trừ khi có -n: đánh số liên tục cả khoá).
  • Gặp lecture/quiz/practice/role-play: tăng bộ đếm, tên "{counter:03d} {sanitize(title)}", gắn vào chapter hiện tại. Nếu chưa có chapter nào thì tạo chapter "giả" từ chính phần tử đó.
  • Ghi lại lecture_count từng chapter, tổng chapter và tổng lecture.
Hệ quả quan trọngSố thứ tự trong tên file là bộ đếm theo chapter, không phải id của Udemy. Nếu tác giả khoá học chèn thêm một bài vào giữa chapter, các bài phía sau sẽ đổi tên và bị tải lại. Bản Go nên lưu thêm manifest có lecture_id (Phase 4) để nhận ra trường hợp này.

4.7 Chọn nguồn video và chất lượng

  • Nguồn mp4 trực tiếp: label là chiều cao (ví dụ "720"); chiều rộng suy ra từ bảng HEIGHT_TO_WIDTH; bỏ nguồn "audio".
  • HLS: tải master playlist, ghi ra temp/index_{asset}.m3u8. Với mỗi variant có cả resolution và codecs, khử trùng theo chiều cao, tải playlist con và ghi ra temp/index_{asset}_{w}x{h}.m3u8. Nguồn được trả về dạng file:// để yt-dlp đọc từ đĩa (vì link gốc cần header/cookie).
  • Chọn chất lượng: mặc định lấy cao nhất. Với -q N: chọn nguồn có |height − N| nhỏ nhất (tức là gần nhất, không bắt buộc ≤ N).

4.8 Tải và resume

  • HLS: yt-dlp --enable-file-urls --force-generic-extractor --concurrent-fragments N --downloader aria2c. yt-dlp giữ file .part và .ytdl nên chạy lại sẽ tải tiếp.
  • File trực tiếp, caption, asset: aria2c -x16 -s20 -j16 -c --auto-file-renaming=false: 16 kết nối mỗi server, chia 20 đoạn, -c để tải tiếp file dở. Mã thoát khác 0 thì ném exception, được bắt ở nơi gọi và ghi vào danh sách lỗi.
  • Idempotent theo tên file: trước mỗi lecture/caption/quiz, nếu file đích đã tồn tại thì bỏ qua và tăng bộ đếm already_present. Cuối cùng in tổng kết: đã tải, đã có, thất bại (kèm danh sách để chạy lại).
  • Media URL có hạn: link ký sẵn trong curriculum hết hạn sau một thời gian, nên resume luôn cần gọi lại API chứ không dùng lại cache cũ.

4.9 Phụ đề

  • Lấy ngôn ngữ theo thứ tự ưu tiên language → srclang → label → locale_id. Lọc theo -l (hoặc all).
  • VTT được tải về, chuyển sang SRT và xoá VTT (trừ --keep-vtt). Bản chuyển đổi chép từng trường giờ/phút/giây/mili-giây, vì các thuộc tính *_in_seconds của webvtt-py làm tròn mất phần mili-giây. Text được html.unescape.
  • Kiểm tra "đã có" chấp nhận cả file .vtt lẫn .srt tương ứng. Thử lại tối đa 3 lần (đệ quy).

4.11 Quiz, practice, role play

  • Quiz: nếu quiz chỉ có 1 assessment loại coding-problem thì là coding assignment (instructions, test files, solution files); ngược lại là quiz thường. Dữ liệu được nhúng vào template HTML.
  • Nhúng JSON an toàn: json.dumps(data).replace("</", "<\/") để chuỗi chứa </script> không đóng thẻ script sớm (chống XSS trong file offline).
  • Role play: dữ liệu chỉ có trong trang Next.js. Thuật toán: (1) gom các chunk self.__next_f.push([type, "chunk"]) thành một payload; (2) duyệt từng dòng id:json, tìm theo chiều sâu object có scenario cùng aiCharacter/learnerRole/meeting; (3) thay mọi tham chiếu "$id" bằng chunk tương ứng: chunk text dạng id:T<độ dài hex>,<text> được cắt theo số byte UTF-8 chứ không theo số ký tự.

4.12 Hậu xử lý H.265

  • libx265 -crf 28 -preset medium, hoặc hevc_nvenc -rc vbr -cq N -b:v 0 với preset x265 được map sang p1–p7.
  • Gắn tag hvc1 để QuickTime và Safari phát được.
  • Ghi ra .tmp rồi os.replace (thay thế nguyên tử); encode lỗi thì xoá .tmp, giữ bản gốc. Chạy với nice -n 7.
  • Thực đo trên M1 Pro: libx265 chỉ ~2–3x realtime, nên bạn đã tắt. Bản Go sẽ dùng hevc_videotoolbox (encoder phần cứng của Apple), chạy nền sau khi tải.

5.2 Phát hiện lệch dòng (drift check)

Vấn đề thực tế đã gặp: index khớp hoàn toàn nhưng nội dung bị dịch lệch một cue (câu của cue 511 nằm ở cue 510…), vì LLM gộp hai cue ngắn. merge không thể phát hiện vì nó chỉ kiểm tra index.

Ý tưởng: độ dài một câu dịch tương quan mạnh với độ dài câu gốc. Nếu một đoạn bị lệch, độ dài bản dịch sẽ tương quan với cue bên cạnh tốt hơn với chính cue của nó.

Với mỗi cửa sổ W = 30 cue, bước nhảy S = 10:
  r0   = corr(len_en[i], len_vi[i])        i trong cửa sổ
  r±1  = corr(len_en[i], len_vi[i ± 1])
  Gắn cờ nếu max(r−1, r+1) − r0 > 0,2
Bỏ qua cửa sổ có < 15 cặp hoặc độ dài hằng số (tương quan không xác định).

Kết quả: phát hiện đúng đoạn WebRTC cue 510–538 mà các bước kiểm tra khác bỏ sót; sau khi sửa, toàn khoá có 0 cảnh báo.

8.1 Bảy nguyên tắc chống lỗi chồng lỗi

  2. Python là chuẩn đối chiếu (oracle): cho tới hết Phase 5, mọi output của Go được so tự động với output Python trên cùng dữ liệu đầu vào (differential testing).

12. Setup dự án và tổ chức code chuẩn production

12.1 Nguyên tắc nền

Không có package util, helper, commonGo Blog chính thức ("Package names") khuyên tránh các tên này: chúng không nói lên bên trong có gì, phình to vô hạn, kéo theo phụ thuộc lung tung và dễ trùng tên khi import. Thay vào đó, mỗi khối dùng chung là một package nhỏ đặt tên theo việc nó làm, ví dụ retry, procexec, atomicfile, srt, và chỉ tách ra khi có ít nhất 3 nơi dùng thật.
  1. Chia package theo nghiệp vụ, không theo tầng kỹ thuật. Không có models/, services/, repositories/ chung cho cả app. Mỗi nghiệp vụ (library, progress, download…) tự chứa model, service và interface nó cần.
  2. Ports & adapters ở mức vừa đủ. Package nghiệp vụ khai báo interface nhỏ cho thứ nó cần từ bên ngoài (đặt ở phía dùng, không phải phía cài đặt). Mọi thứ chạm tới thế giới bên ngoài (SQLite, Udemy, Chrome, yt-dlp, ffmpeg, Claude) nằm trong adapter/. Không tạo interface cho code nội bộ thuần tuý.
  3. Phụ thuộc một chiều, được lint kiểm tra. Nghiệp vụ không import adapter/ hay transport/. Chỉ app/ (composition root) biết tất cả và lắp ráp chúng. Quy tắc này được depguard trong golangci-lint cưỡng chế, không dựa vào trí nhớ.
  4. Không trạng thái toàn cục. Không biến global, không init() có tác dụng phụ (trừ đăng ký driver), mọi phụ thuộc truyền qua constructor.
  5. Mọi I/O nhận context.Context làm tham số đầu; mọi goroutine có chủ sở hữu (errgroup) và dừng được khi tắt app.
  6. Ưu tiên thư viện chuẩn, thêm thư viện ngoài khi nó xoá được boilerplate thật hoặc giảm rủi ro thật. Mỗi thư viện ngoài ở bảng 12.3 đều có lý do và có phương án đã loại.
  7. Hợp đồng sinh code: API (OpenAPI), truy vấn SQL (sqlc) và migration (goose) là nguồn sự thật; code Go/TS sinh ra từ đó, không viết tay hai lần.

12.5 Quy ước viết code

Lỗi

  • Package nghiệp vụ khai báo lỗi có tên: var ErrLectureNotFound = errors.New(…) hoặc kiểu lỗi mang dữ liệu.
  • Bọc lỗi kèm ngữ cảnh: fmt.Errorf("scan chapter %q: %w", dir, err).
  • Chỉ transport/http đổi lỗi sang HTTP status, ở một chỗ, trả về application/problem+json (RFC 9457).
  • Không nuốt lỗi; lint errcheck, errorlint, nilerr bắt các trường hợp sót.

Bí mật

  • Kiểu config.Secret có String() và LogValue() trả về [REDACTED]: token Udemy, API key không thể lọt vào log dù vô tình in cả struct.
  • Token truyền cho tiến trình con qua biến môi trường, không qua tham số dòng lệnh.
  • Fixture test có test riêng quét chuỗi nhạy cảm.

API của package

  • Constructor New(deps Deps) *Service; nhiều tham số thì dùng struct.
  • Nhận interface, trả về struct cụ thể. Interface 1–3 method.
  • Export tối thiểu; mọi thứ khác viết thường.
  • Hằng số có tên cho mọi ngưỡng (5 giây lưu tiến độ, 95% hoàn thành…).

Vòng đời

  • signal.NotifyContext bắt Ctrl-C/SIGTERM → http.Server.Shutdown, huỷ job, chờ tiến trình con thoát, đóng DB.
  • Mọi worker chạy trong một errgroup; một worker chết thì app tắt có trật tự, không treo.
  • Health: GET /healthz; phiên bản build gắn bằng -ldflags.

Tên file: Go dùng chữ thường, gạch dưới khi cần (course_scanner.go, course_scanner_test.go). Đây là lệch có chủ đích so với quy tắc kebab-case chung của bạn, vì kebab-case không phải quy ước Go. Frontend vẫn theo kebab-case, riêng file component theo tên component.

12.8 Định nghĩa "xong" cho mỗi thay đổi

  1. task check xanh trên máy và trên CI.
  2. Có test cho hành vi mới, gồm cả nhánh lỗi.
  3. Không có TODO, code bị comment, hay //nolint thiếu // reason: ….
  4. Log không chứa bí mật; lỗi có đủ ngữ cảnh để debug.
  5. Commit nguyên tử theo <type>(<scope>): …; port và sửa lỗi không nằm chung commit.
